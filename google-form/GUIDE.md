# Google 表單版｜婚禮商單三份表單

同一個 Apps Script 檔（`Code.gs`）裡有三個函式，各別執行就各建一份表單，回覆全部直接進試算表。

| 函式 | 表單 | 結構 | 收集 Email | 送出後可改 |
|---|---|---|---|---|
| `createWeddingStoryForm` | 婚禮故事採集卡 | 9 區段／24 題／18 必填 | 否 | 是 |
| `createPortraitConsentForm` | 肖像使用授權書 | 4 區段／16 題／12 必填 | **是**（留簽署紀錄） | 否 |
| `createRevisionPolicyForm` | 修改約定確認單 | 4 區段／16 題／14 必填 | **是** | 否 |

## 建立方式（約 2 分鐘，不用碰 API 金鑰）

1. 開 <https://script.google.com/home> → 「新增專案」
2. 把 `Code.gs` 全部貼進去，覆蓋原本內容，存檔
3. 上方函式下拉選要建的那一份 → 按「執行」
4. 首次會跳出授權：同一個 Google 帳號 → 「進階」→「前往（不安全）」→ 允許
   （要「查看、編輯、建立及刪除你的 Google 表單」權限，這是 Apps Script 跑 Forms API 的必要範圍）
5. 「執行記錄」會印出：填寫連結、編輯連結、回覆試算表網址

重複執行會再建一份新表單，不會動到舊的。**所有條文數字集中在 `Code.gs` 最上方的 `CONFIG`**，改一處三份表單都跟著對（免費修改次數、加收金額提示、刪除天數、下線天數、可發布平台清單）。

## A. 肖像使用授權書（對應你給的模板 A）

條文全文放在表單說明，題目把「空白」變成可勾選、可留證的欄位：

| 模板原文 | 表單怎麼問 |
|---|---|
| 授權人 | 1-1／1-2 新郎、新娘姓名（必填） |
| 使用範圍三個 □ | 2-1 單選三選一（必填，不給「其他」） |
| 平臺：【】、是否打碼：【】 | 2-2 平台多選（IG／FB／YouTube／小紅書／官網／媒體投稿）＋2-3 打碼方式 |
| 第 4 條 刪除天數 | 3-1 單選 30／60／90 天＋其他 |
| 第 5 條 下線天數 | 3-2 單選 7／14／30 天＋其他 |
| 第 3 條 不得轉交第三方 | 3-3 勾選確認三項（必填） |
| 簽字、日期 | 4-1～4-5 雙方簽名＋日期＋「我同意」 |

設計上的兩個判斷：

- **2-1 用單選不用多選**：三個範圍互相排斥（「不同意公開」不可能同時「同意公開」）。多選會出現自相矛盾的組合，事後難主張。
- **這份開「收集 Email」**：等於把同意綁在一個 Google 帳號上，多一層可追溯。代價是新人要登入 Google；不接受的話，把 `CONFIG` 之後那一行 `true` 改成 `false` 即可。

## B. 修改約定確認單（對應你給的模板 B）

| 模板原文 | 表單怎麼問 |
|---|---|
| 文案免費修改【】次 | 2-1 單選 1／2／3 次 |
| 單鏡頭免費重做【】次 | 2-2 單選 1／2／3 次 |
| 預覽免費一輪統一意見 | 2-3 單選 1／2 輪 |
| 超出每次加收【】元 | 2-4 文字（每次議價填一次） |
| 文案確認後改內容 | 2-5 單選：依加收標準計費／重新報價／不做 |
| 延遲則順延 | 3-1 勾選確認 |
| 其他約定 | 3-2 文字 |
| 簽字、日期 | 4-1～4-5 |

補強的地方：模板只寫「單個鏡頭不滿意重做」，沒說「改鏡頭內容算什麼」。表單在 2-2 的說明直接寫明：**改動鏡頭內容視為文案變更，走 2-4 加收**。這是婚禮片最常吵的一條。

## 兩個模板都補了「個資告知」

三份表單的說明都帶一段依《個人資料保護法》第 8 條寫的告知事項（蒐集者、目的、類別、期間、地區、對象、方式、當事人權利、不提供的影響）。表單一收集姓名與故事就適用，少了這段是實務上最常見的缺漏。

## 與 14 步流程的接法

| 送出什麼 | 對應 skill 步驟 |
|---|---|
| 肖像授權書 | 第 1 步之前（沒有授權不該開始生圖） |
| 修改約定 | 報價／接單時（第 1 步之前） |
| 故事採集卡 | 第 1 步「故事採集」 |
| 採集卡那一列試算表 | 整理成 `FACTS.md` 的原料（新人原話優先，不改寫事實） |
| 回傳故事卡給新人確認 | 第 3 步的依據 |

⚠️ 表單原文**不等於**已確認文案。`FACTS.md` 由製作方整理後仍要回傳新人確認，這是流程裡不能省的一關。

## 誠實的邊界

- **這不是法律意見。** 條文是你給的，我只負責把它做成可填、可簽、有時間戳、有帳號紀錄的形式。實際效力、違約金是否過高、要不要公證，請找律師看過一次再上線。
- **電子同意的舉證力弱於親簽紙本。** Google 表單能證明「某個帳號在某時送出、內容為何」，不能證明「本人親簽」。單價高的案子建議：線上填完 → 匯出 PDF 或印出簽名頁 → 雙方親簽各留一份。
- **檔案上傳不建議開。** 開了就要求填答者登入 Google，且照片會進你的 Drive（授權書第 4 條的刪除義務你就要真的執行）。
- **我已驗證的是結構**（區段數、題數、必填數、題型、選項、說明文字、回覆試算表掛載），用 mock 跑過三份函式；**沒驗證的是它在你的 Google 帳號上實際產生的樣子** —— 那要你執行一次才知道。

## 與網頁卡的差異

|      | 網頁卡（GitHub Pages） | Google 表單 |
| ---- | -------------------- | --------- |
| 品牌感  | 可完全自訂（默墨文創抬頭、字體、配色、favicon） | 只能改標題與說明，樣式是 Google 的 |
| 回覆收集 | 新人要「複製故事卡」再用 LINE 貼回 | 直接進試算表，一列一單 |
| 照片   | 一律走 LINE | 可開檔案上傳（但要登入 Google，不建議） |
| 適合   | 想留品牌質感、單量少 | 單量多、要集中管理、要算流程 |

## 已知取捨

- 表單不能做「一題一行的故事卡摘要」。要那段文字用網頁卡，要整齊資料列用表單。
- 採集卡第 19 題在網頁卡是「勾選＋各自填細節」，表單只能用多選＋「其他」一欄。
- 採集卡第 6-2 題在網頁卡是選了非寫實畫風才出現；表單沒有條件顯示，做成選填並在說明寫清楚。
- 題號刻意與網頁卡一致（1、2-1、2-2、4、5、6、6-2、7–23），兩邊對照不會錯位。
